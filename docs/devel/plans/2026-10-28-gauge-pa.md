# Gauge PA: Implementation Plan (1.2)

Design: `2026-10-28-klipper-companions-design.md` (same directory). This plan states
interfaces, tests and constraints; bodies are the implementer's. Branch `feature/gauge-pa`.

## What already exists and is reused

- **`helix::pacal`** (`include/pa_calibration.h`, `src/printer/pa_calibration.cpp`): the
  provider table for firmware that measures PA (Snapmaker U1, FlashForge eBoard), with
  `detect_object` for commands a klippy extra registers. `PACalibrationPanel`
  (`ui_xml/calibration_pa_panel.xml`) and `MoonrakerAdvancedAPI::start_pa_calibrate` run any
  row. **The K2 is one new row; no new table.**
- **PA tuning storage** (`docs/devel/PRESSURE_ADVANCE_TUNING.md`): `tune::set_pressure_advance`,
  `PaTuningOverlay::save_to_spool` (Spoolman extra `pressure_advance`),
  `PaTuningOverlay::publish_to_moonraker` + `pa::merge_moonraker_record`
  (`helix-screen`/`pressure_advance`), `apply_saved_pressure_advance` at activation.
- **Pre-print options** (`include/pre_print_option.h`, printer DB options): the U1 already has
  `flow_calibrate` ("Pressure Advance Calibration").
- **Plugin framework** (`moonraker-plugin/helix_print.py`): `_load_sibling`, `register_feature`,
  per-feature tests in `moonraker-plugin/tests/`.
- **Gauge prototype** (`.claude/scratchpad/k2-strain-gauge-pa/`, gitignored): the working
  sampler, fit, four captured runs and the routine G-code. Proven on a stock K2 Plus.

## Decisions taken in this plan

1. **The companion runs the whole measurement in Klipper:** sampling, routine and fit (the fit
   in a subprocess so the reactor never stalls). A print-time run must block the start and
   apply its result with no screen connected, so nothing the measurement needs lives in the
   app or the plugin.
2. **The companion keeps its own measured cache** (`<config>/helix_pa_gauge.json`, keyed by
   filament identity + nozzle temperature) for `MODE=auto` and the per-lane apply at tool
   changes. The user-facing record stays the app's: when the app sees a result it saves it
   through the existing PA tuning store, now with a `source` field. The plugin never writes
   the PA record (two writers of one schema is the drift this repo forbids).
3. **The plugin is the installer only** for companions (`helix_companions.py`), plus a
   `pa_gauge` feature switch (opt-in: it heats and moves).
4. **Per-printer routine data is a profile table inside the companion**, chosen by detection:
   `creality_cfs` (reads `[box]` `extrude_pos_*`, `clean_left_pos_x`; brackets with
   `BOX_START_PRINT`/`BOX_END_PRINT`; wipes with `BOX_NOZZLE_CLEAN`) and `generic` (purge
   position, wiggle span and prepare/finish G-code from the companion's own config section).

## Phase 1: the companion (Klipper side)

Files: `moonraker-plugin/klippy/helix_pa_gauge.py`, `moonraker-plugin/klippy/helix_pa_fit.py`.
Python: Klipper's interpreter (3.7+), pure stdlib.

- **Force sources** (table, first that answers wins):
  - `prtouch`: handles built with `mcu.lookup_query_command` from the formats
    `start_prtouch_pres oid=%c cfg_regs=%c acq_tick=%u ned_tftr=%c ned_hftr=%c ned_lftr=%u
    min_hold=%i max_hold=%i add_hold=%i lmt_dead=%u`, `read_prtouch_pres oid=%c is_src=%c
    ch=%c idx=%c len=%c` (response `resault_prtouch_pres ... ticks=%.*s datas=%.*s`),
    `stop_prtouch_pres oid=%c sta_swap=%c`; oid and MCU from `prtouch_v3.pres`. Refuses while
    a probe is active.
  - `load_cell`: `printer.lookup_object('load_cell')`, `add_client(cb)`.
- **Commands:**
  - `HELIX_PA_CALIBRATE [TEMP=] [MODE=full|quick|auto] [SLOT=]`: the routine (home if
    needed, purge position, heat, feed bracket, prime, sweep, fit, apply, wipe, cool unless
    called from a print start). Console lines, matched by the pacal row:
    `HELIX_PA: step <i>/<n>`, `HELIX_PA: measured K=<k> (<quality>)`,
    `HELIX_PA: no result: <reasons>`.
  - `HELIX_PA_LOG_START/MARK/STOP`: kept for diagnostics.
- **Status:** `{version, available, reason, source, profile, running, last: {k, reliable,
  problems, snr, stamp, filament}}`.
- **Never fails Klipper's ready callback:** every lookup wrapped; failure = `available:false`
  with the reason.
- **Tests** (`moonraker-plugin/tests/test_helix_pa_gauge.py`, `test_helix_pa_fit.py`, fake
  printer/MCU/reactor): ready hook with no `prtouch_v3`, with a `pres` lacking `oid`, with
  `trapqs` instead of `dtrapqs` (each `available:false`, none raises); window decoder on a
  captured frame; routine G-code for both profiles; fit on captured runs: run3/run4 result in
  0.08-0.09 and reliable, run2 (extrude-only) rejected as flat, glitches injected still pass.
  Fixtures: run2 + run4 gzipped; check their size before committing.

## Phase 2: plugin installs companions

Files: `moonraker-plugin/helix_companions.py`, `install.sh`, `remote-install.sh`
(`PLUGIN_FILES`), `helix_print.py` (`_start_companions`).

- `CompanionManager(plugin)`: at Klippy ready reads `printer.info` `klipper_path`; for each
  enabled companion whose plugin-side probe passes (`prtouch_v3` or `load_cell` in the object
  list for `helix_pa_gauge`), links the module into `<klipper_path>/klippy/extras/` (copy when
  a link is refused), writes `<config>/helix_companions/<name>.cfg`; reverse order on removal.
  Reports `restart_pending` when the loaded version differs from the bundled one.
- Recovery: Klippy `error` naming a `helix_` section -> re-link, `RESTART`. The only restart
  it sends unasked.
- `install.sh`: adds `[include helix_companions/*.cfg]` (backup first); uninstall removes it,
  the dir and every link it made.
- Features: `klipper_companions` (always on, reports the per-companion map) and `pa_gauge`
  (switch, `acts=True`, default off).
- **Tests** (`test_helix_companions.py`): install order, removal order, disabled feature
  removes both, failing probe installs nothing, missing `klipper_path` reports, recovery only
  for a `helix_` section error, no restart while printing or paused.

## Phase 3: app

- `pacal` row `kHelixGauge`: `detect_object="helix_pa_gauge"`, `gcode="HELIX_PA_CALIBRATE
  TEMP={temp}"`, patterns above, `applies_result=true`, `per_tool=false` (calibrates what is
  loaded), estimate measured in Phase 1. Tests in `tests/unit/test_pa_calibration.cpp`.
- **Save for every provider**: after a run the panel saves the measured K through the PA
  tuning store (Spoolman + `merge_moonraker_record`), with `source` (`"measured:<provider>"`
  vs `"tuned"`) added to `pa::SavedK` and the record. Tests: `[pa_tuning]` record round-trip
  with and without `source`.
- **Slot action**: `AmsContextMenu` `CALIBRATE_PA`, shown when `pacal::is_supported(hw)` and
  the slot is loadable; loads the slot through the backend, then opens the PA panel already
  running. Decision function `slot_offers_pa_calibration(...)` pure, tested.
- **Pre-print toggle (K2)**: printer DB option `pa_measure` (`pre_start_gcode`
  `HELIX_PA_CALIBRATE MODE=auto`), gated on the plugin feature `pa_gauge` Ready.
- **Slicer-override flag**: `helix_gcode_reader.py`'s existing `SET_PRESSURE_ADVANCE` reducer
  feeds a new analysis field `sets_pressure_advance`; the toggle's hint warns when the file
  sets PA itself. Tests: analysis pytest + `[plugin_feature]`.
- Plugin feature rows: `kKnownPluginFeatures`, `kPluginSwitchFeatures`, mock entry.

### Phase 3 status (2026-10-29)

Done and on the branch:

- `pa_result_store` (`include/pa_result_store.h`): one spool lookup, Spoolman write and
  Moonraker record for the tuning overlay and the calibration panel. `SavedK.source` is
  `tuned` or `measured:<provider id>` (new stable `id` per pacal row).
- The calibration panel records every measured K and offers Save to Spool beside Re-measure.
- `pa_gauge` switch in Settings > Printing, shown only where `printer_can_add_pa_cal`
  (`pacal::can_add_measuring`: `prtouch_v3`, `load_cell`, `load_cell_probe`). The plugin
  reports `no_force_sensor` elsewhere and syncs companions when a status read finds the
  switch changed, so the app needs no extra call. Feature rows, reasons, mock entry.
- Analysis field `sets_pressure_advance`.
- AMS slot menu Calibrate PA on the loaded slot of a measuring printer; opens the panel at
  the spool's temperature with its material on the result. Unloaded slots are not offered:
  loading first needs the CFS on the bench.

Not done, waits for the printer: print-time measuring (the design's in-start step after the
first load, the per-lane table and apply on each CFS change), its toggle, and the app reading
`sets_pressure_advance` for that toggle's hint. It cannot ship before the printed
comparison anyway.
