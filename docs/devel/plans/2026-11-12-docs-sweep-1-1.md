# 1.1 Documentation Sweep Implementation Plan

> **For agentic workers:** Wave A is code: use superpowers:executing-plans (or subagent-driven-development) task by task. Waves B-G are content: run them as a Workflow, one writer and one checker agent per page group, under the protocol in § Content waves. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every doc image reproducible from one command, then rewrite and claim-check the user manual (gating 1.1 final) and the dev docs (after), as the design describes.

**Architecture:** Wave A replaces the two capture scripts with one manifest (`docs/images/doc-screenshots.yml`) read by `scripts/doc_screenshots.py`, which drives a headless `--test` instance through `helix-screen ctl`, crops to a named widget, and draws numbered markers anchored to named widgets. A fast lint keeps docs and manifest in step. Waves B-G are content passes that use that tooling.

**Tech Stack:** Python 3 in `.venv` (PyYAML 6, Pillow 10+ already in `requirements.txt`), `helix-screen ctl` (`screenshot --target`, `geom`), bash `scripts/qc/` gate, bats meta-test, pytest in `tests/python/`.

**Spec:** `docs/devel/plans/2026-11-10-docs-sweep-1-1-design.md`

**Branch:** `docs/docs-sweep-1.1` off `origin/release/1.1`, worktree `.worktrees/docs-sweep-1.1`. Lands on `release/1.1`, merged forward to `main`.

## Global Constraints

- App shots are 800x480 unless the manifest entry's `size` says otherwise; non-app images are `kind: manual` entries.
- Callouts: crop to a named widget's box plus a margin, numbered circular markers drawn on the image, a numbered list under the image in the page. No text drawn into images.
- Capture is headless only: `HELIX_HEADLESS=1 SDL_VIDEODRIVER=dummy`, `--test`, socket and config dir pinned per run (root `CLAUDE.md` § Driving the UI). Never against a real printer.
- `guide/getting-started.md`, `UPGRADING.md` and the guide index are never renamed (QR codes on shipped devices). Moved pages get nav entries and redirects in `prestonbrown/helixscreen-website`.
- User docs follow `docs/user/CLAUDE.md`: step-by-step, no source references, copy-pasteable commands. Full sentences; no em dashes.
- A page is done only after a checker agent that did not write it has checked every factual claim against the code (and a mock run where the claim is about the screen).
- Subagents run Opus or lower, model passed explicitly. Each content wave states its agent count before it starts.
- Verification cadence (root `CLAUDE.md`): pytest/bats for the tooling once per task; one `make land-gate` per landing batch; docs-only landings do not need a second full gate.

## Review Focus

1. **A widget a marker or crop names is renamed or hidden by a later UI change**: the regen must fail loudly naming the entry and widget, never write a blank or mis-cropped image. Pinned in Task 2 (`test_missing_anchor_fails_entry`).
2. **An image referenced with a relative path from a nested page** (`../../images/user/x.png`, `<img src=...>`): the lint must resolve it to the same file the manifest names. Pinned in Task 3 (`test_resolves_relative_and_html_refs`).
3. **A manifest entry whose file nothing references** (dead image): reported by the lint as unreferenced, not silently kept. Pinned in Task 3.
4. **A capture that races an animation or async load**: entries use `ctl screenshot --stable`; an entry may add `wait_idle` steps. Pinned in Task 2 (`test_capture_uses_stable`).
5. **Running on a Mac**: `make doc-screenshots` must work with `gmake` and with the venv python, and refuse clearly when the app binary is missing. Pinned in Task 4.

## Wave A: screenshot tooling (code)

### Task 1: The manifest and its loader

**Files:**
- Create: `docs/images/doc-screenshots.yml`, `scripts/doc_screenshots.py` (loader section), `tests/python/test_doc_screenshots.py`

**Interfaces (produces):**
- Manifest schema (YAML list under `images:`), one entry per image:
  - `path` (str, repo-relative, under `docs/images/`), required
  - `kind`: `app` | `manual`, required
  - app entries: `recipe` (a token in `scripts/screenshot-recipes.sh`) or `steps` (list of `ctl` command strings), exactly one; `env` (map, e.g. `HELIX_MOCK_AMS: medusahc`), optional; `size` (`WxH`, default `800x480`); `crop` (widget name, optional; absent = full screen); `margin` (px, default 12); `markers` (list of `{n: int, widget: str, at: center|top_left|top_right|bottom_left|bottom_right}`, default `at: top_right`)
  - manual entries: `source` (str) and `recapture` (str), both required
- `load_manifest(path: Path) -> list[Entry]` where `Entry` is a frozen dataclass mirroring the fields; raises `ManifestError(entry_path, reason)` on: missing required field, both or neither of `recipe`/`steps`, unknown recipe token, duplicate `path`, marker `n` repeated within an entry, `kind: manual` carrying app fields.

- [ ] **Step 2:** `.venv/bin/python -m pytest tests/python/test_doc_screenshots.py -q` → FAIL (module missing).
- [ ] **Step 3:** implement the loader; seed the manifest with every entry from `scripts/screenshot-all.sh` `PANELS` and `scripts/generate-screenshots.sh` `SCREENSHOTS` (same output paths), and a `kind: manual` entry for each existing image neither script makes (the ~45 the inventory lists), `source`/`recapture` filled from the image and its page.

- [ ] **Step 5:** commit `docs(tooling): one manifest for every doc image`.

## Content waves (B-G)

### Protocol (every wave)

Per page group: one **writer** agent and one **checker** agent (never the same). Agent count stated to Preston before the wave starts.

- **Writer:** reads the page(s), `docs/user/CLAUDE.md` (or `docs/devel/CLAUDE.md`), the relevant `CHANGELOG_1_1_DRAFT.md` entries, and the code the page describes; rewrites for accuracy, clarity and concision; adds manifest entries and callouts (Task 1 schema) where a picture helps; regenerates its images with `make doc-screenshots ONLY=...` on zeus; commits on the wave branch. Writes a claims list: one line per factual claim with the file or mock action that backs it.
- **Checker:** gets the page and the claims list, not the writer's reasoning; checks every claim against code and, for screen claims, a headless mock run; returns `confirmed | wrong (fix) | unverifiable (why)` per claim. Writer fixes; checker re-checks only the changed claims.
- **Coverage table** per wave: each `CHANGELOG_1_1_DRAFT.md` Added/Changed entry in scope → the page that documents it, or "not user-facing".
- **Wave report** (written first, filled as it goes): pages done, claims checked / fixed / unverifiable, issues filed, images added, deletions.
