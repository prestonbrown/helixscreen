# ESP32 Port — Plan 4: App Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The real HelixScreen UI shell — home, temps, motion, macros/console, print select/status, settings, AMS — boots and runs on the K-Touch against a live Moonraker printer, with assets on LittleFS, per-tier compiled fonts, WiFi provisioning, and persistent settings.

**Architecture:** Seams-first hybrid per `docs/devel/plans/2026-07-13-esp32-native-port-design.md`. Plans 1–3 delivered the firmware skeleton (boot/display/touch/OTA layout), the main-tree seams (asset root, token table, `ConfigStorage`, WiFi factory hook), and the network layer (`EspMoonrakerClient` implementing `IMoonrakerClient`, HIL-passed vs a live Voron). This plan builds `components/helixapp` (curated app core from `src/`), stages assets to LittleFS, writes the ESP boot sequence, and wires live printer data — staged so the visible milestone (real shell on glass) lands first.

**Tech Stack:** ESP-IDF v5.5 (`~/Code/esp-idf`, `source export.sh`), LVGL 9.5 + helix-xml (via `components/helixcore`, unmodified), `esp_websocket_client` (helixnet), `esp_http_client`, `joltwallet/littlefs`, GitHub Actions CI with 5.8MB size gate.

## Owner decisions folded in (Preston, 2026-07-15)

1. **Plugins: excluded outright on ESP32.** No dlopen shim, no runtime skip — compile gate, code absent from image.
2. **Timelapse: split gate.** Printer-side capture control (JSON-RPC `machine.timelapse` settings) ships; on-device *viewing* (video list/download/playback) is gated off.
3. **Spoolman: ships in v1.** Verified pure JSON-RPC (`server.spoolman.*` proxy via WebSocket) — the design spec's "gated off" entry is superseded.
4. **Printer images: ship as many as possible.** The device is a multi-printer remote screen; displaying the configured printer's image is a requirement. Build-time downscale+quantize pipeline; fetch-and-cache fallback only if measurement forces it.
5. **Assets ship in a packed compressed single-file container** (approved 2026-07-15 after Task 2's LittleFS block-overhead finding): read-only compressed FS on the `storage` partition (frogfs or custom helixpak), POSIX-VFS mounted at `/assets`. Kills 4KB-per-file rounding + ~3–4:1 text compression → all 9 languages and all 71 printer images fit. `cfg` littlefs partition unchanged for mutable settings. SQLite assessed and rejected.
6. **Repartition to 6.875MB OTA slots / 2.0MB storage** (approved 2026-07-15 after Task 5 forensics): the full-shell image is ~6.19MB post font-dedup — over the old 6.0MB slots; the container freed the storage room to grow slots instead of cutting v1 features. Plan 5's CJK (+~0.9MB) will still require ~0.3–0.4MB of .text diet later — carried as a Plan 5 note.

## Global Constraints

- Target: BTT K-Touch only (ESP32-S3R8, 8MB octal PSRAM @80MHz, 16MB flash, 800×480 RGB + GT911). 800×480 selects the **`_medium` breakpoint tier**.
- **Image budget ≤7,004,160 B** (6.875MB OTA slot − 200KiB margin; `size_budget.json`), CI-enforced every commit. (Amended 2026-07-15 after Task 5 forensics, owner decision #6: slots grown 6.0→6.875MB by shrinking storage 3.75→2.0MB — the packed asset container uses only 1.73MB. Final partition-table change before release. Layout: ota_0 0x20000/0x6E0000, ota_1 0x700000/0x6E0000, storage 0xDE0000/0x200000, cfg 0xFE0000/0x20000.)
- **Storage partition 2.0MB** — the packed frogfs container (currently 1,732,876 B, ~0.3MB headroom) must fit with the size report printed at build time.
- **RAM budgets (HIL-asserted):** PSRAM ≥1.5MB free steady-state with shell + live Moonraker + AMS; internal SRAM ≥100KB; boot to rendered UI ≤10s.
- **THE PATTERN (2026-07-15, af33cb375): no runtime internal-RAM allocation ≥32KB after WiFi start.** Big buffers/stacks are static `.bss`, PSRAM, or allocated before `net` task spawn. WiFi fragments internal heap (largest block measured 31744 < 32768).
- **No periodic `heap_caps_get_largest_free_block()` / `heap_caps_get_info()` / integrity checks while the display is live** — one corrupted frame per call. Steady-state telemetry = `heap_caps_get_free_size()` only.
- Every task that runs app code is **pthread-created** (ESP-IDF `pthread_self()` and C++ `std::this_thread` require it), ≥32KB stack if it touches XML/expat. `LV_USE_OS` stays `LV_OS_NONE` (the hidden 32KB draw-thread stack was boot-lottery defect #2).
- `esp_websocket_client` callbacks are a background FreeRTOS task: the existing `ui_queue_update()` / `tok.defer()` discipline applies unchanged.
- **SECURITY: WiFi credentials must NEVER be committed** (public repo). Real SSID/PSK live only in git-ignored `sdkconfig.local`. Run a credential grep on the staged diff before every commit.
- Never open the CH340 serial port casually — pyserial asserts DTR/RTS on open, resetting the chip. Boot validation uses `boot_harness.py` (session scratchpad; recipe in memory `project_esp32_plan3_network_complete.md`): 20-trial minimum, dual oracle (ping AND "entering render loop"), per-trial reset-cause counts.
- Builds: `source ~/Code/esp-idf/export.sh`, `rm -f sdkconfig` after any defaults change (stale sdkconfig silently wins), `idf.py build` in background tasks; flash via `sg dialout -c "python -m esptool ... write_flash @flash_args"` at 460800.
- Desktop stays green: every main-tree change runs `make test-run` (all shards) before commit. Main-tree commits `feat(esp32)`/`fix(esp32)`; firmware-tree commits `feat(esp32-fw)`.
- HIL steps need the physical K-Touch and (where marked) Preston's visual confirmation — one HIL cycle at a time. Destructive printer RPCs (print start on the Voron) need Preston's explicit OK first.
- Branch: `esp32/port-4-app` off `041e954c8`, worked in the existing `.worktrees/port-3-network` worktree (dir name lags branch; noted in ledger).

### Task 3: Packed compressed asset container + printer images (owner-approved amendment 2026-07-15)

**Why (supersedes the original "printer-image diet" framing):** Task 2 proved LittleFS charges a 4KB block per file — 308 small ui_xml files cost 1.76MB on-flash for 1.04MB of text (69% overhead), leaving 28KB headroom, zero room for printer images, and zh dropped. A single-file **read-only compressed container** kills the per-file overhead AND gets ~3–4:1 deflate on text assets: projected ~2.5MB free on the same 3.75MB partition — all 9 languages AND all 71 printer images ship. SQLite was assessed and rejected (~400KB library + query shims in every POSIX-path consumer for no format-specific gain).

**Files:**
- Evaluate first: `frogfs` (third-party ESP-IDF component, read-only compressed FS with POSIX VFS — verify current maintenance state, IDF v5.5 compat, deflate support, license). Fallback: `helixpak` — our own ~300-line custom VFS (index + per-file raw-deflate blobs; ESP32-S3 ROM ships a miniz inflater) + Python packer.
- Create: `firmware/helixscreen-esp32/main/` container mount (replacing the Task 2 littlefs mount of the `storage` partition ONLY — the `cfg` littlefs mount at `/config` stays exactly as committed)
- Create: `scripts/esp32_printer_images.py` (image pipeline, unchanged mission)
- Modify: `scripts/esp32_stage_assets.py` (staging tree stays the source of truth; the packer consumes `build/littlefs_staging/`; the size gate moves to PACKED output vs 3.75MB)
- Modify: firmware CMake (partition image = packed container instead of `littlefs_create_partition_image`)

**Interfaces:**
- Produces: `storage` partition holds one packed compressed image, mounted read-only via POSIX VFS at **`/assets`** (Task 6 calls `set_asset_root("/assets")`); asset updates become a single atomic partition write.
- Image pipeline: every image from `assets/images/printers/` re-rendered at the width `PrinterImageManager::get_active_image_path(800)` selects, palette-quantized **favoring quality** (pressure is off), alpha preserved; PNGs stored uncompressed-in-container (already compressed). All 71 ship; per-image + total size report. **Never silently drop.**
- Runtime-write audit: anything that writes under the asset root (e.g., printer-image scale cache) must target `/config` or PSRAM — the container is immutable; this task finds and redirects any such path (main-tree change with desktop tests if needed).
- Boot-cost gate: registration reads ~320 files once; decompression overhead must stay negligible (assert boot-to-UI budget unchanged in HIL).
