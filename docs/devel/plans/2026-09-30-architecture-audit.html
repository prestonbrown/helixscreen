Why the bloat keeps growing

  1. No home for recurring lifecycle. Each new overlay, backend or widget copies the last one: 70 overlays retype create/show/accessor, 9 AMS backends each own override state, 31 widgets hand-manage user_data. See FW-1, AMS-1, FW-13.
  2. Hand-kept parallel lists that drift. Sensor managers listed in 3 places, platform keys, the XML component registry (342), subscription field lists, capability setters (38 lines across 4 files per bool), ESP32 manifests (557 + 271 paths), release/deploy make recipes. Most confirmed bugs came from this. See SYS-4, PRN-5, FW-9, TB-5.
  3. Lint gates standing in for types. About 41K lines of lint infrastructure; several gates guard one bug a type would prevent. See TB-9.
  4. Tests coupled to private state. 7,702 TestAccess call sites freeze implementations and block refactors. See TB-1.
