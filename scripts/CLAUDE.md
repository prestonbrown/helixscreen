# scripts/

Build, asset generation, deployment, and developer tooling for HelixScreen. This index says
what each script is for; the script's own header carries the reasoning behind it.

## Categories

### Installation & Deployment
| Script | Purpose |
|--------|---------|
| `install-dev.sh` | Modular dev installer - uses `lib/installer/` modules. Edit this one |
| `bundle-installer.sh` | Bundles `lib/installer/*` → `install.sh`, the single-file end-user installer (`curl\|sh`). Run through `make installer` → `build/installer/`; never committed |
| `install.sh` | Bootstrap behind the old one-line URL (the raw GitHub URL for main/scripts/install.sh): downloads the release-bundled installer from `https://releases.helixscreen.org/install.sh` (`HELIX_INSTALLER_URL` overrides) with curl or wget and runs it with the same arguments. Docs give the releases URL. Tests: `tests/shell/test_install_bootstrap.bats` |
| `bundle-uninstaller.sh` | Bundles uninstall modules → `uninstall.sh` (`make installer` → `build/installer/`) |
| `render-installer-logo.sh` | Regenerates `lib/installer/logo.sh` (the installer's banner: half-block text art plus kitty, iTerm2 and sixel images) from `assets/images/helix-icon-256.png`, drawing each with `installer_logo_art.py`. Needs python3 with Pillow; the output is committed, so only re-run it when the icon changes |
| `helix-launcher.sh` | Systemd-launched watchdog wrapper. Sources `helixscreen.env` for runtime config |
| `check-deps.sh` | Validates build dependencies. `--minimal` for cross-compile environments |
| `device-env-set.sh` | Idempotently set one `KEY=VALUE` in a deployed device's `helixscreen.env` over ssh. Deploys exclude that file, so this is the only thing that writes it; `sync-device-features` (`mk/cross.mk`) calls it per `bin/.build-features` |
| `device-env-set-remote.sh` | The on-device half, piped to `sh -s` (POSIX sh: the K1/AD5M/CC1/K2 are BusyBox ash). Its own file so `tests/shell/test_device_env_set.bats` can run it without a printer |
| `deploy-stop-app-remote.sh` | The on-device stop step of `deploy-common` (`mk/cross.mk`), piped to `sh -s` before any sync. Stops the systemd units through `systemctl` (root) or `sudo -n`/polkit (anyone else) and exits 3 without killing anything when one stays running, since killing a `Restart=always` unit's process respawns it from a half-synced `bin/`; then kills unit-less instances by name. Tests: `tests/shell/test_deploy_stop_app.bats` |

### Release & Packaging
| Script | Purpose |
|--------|---------|
| `release-gate.sh` | `make release-gate`: what a tag push builds and per-push CI does not, run before tagging. `fast`: VERSION.txt has a CHANGELOG entry and no tag yet, `generate-whatsnew.sh` succeeds (a stable version needs `android/whatsnew/<version>.txt`), installer bundles build. `heavy`: per `RELEASE_GATE_TARGETS` (default `mips`), the `HELIX_PACKAGING=1` docker cross build under a `heavy:release-gate` claim, `make release-<target>`, splash/watchdog present, no mock symbols in the `.sym`. | `release-health.sh` | Newest beta of `VERSION.txt`'s release vs stable in telemetry (releases endpoint, 14d): table, a WARN line per trailing metric, a small-sample note. Always exits 0; also a `release-gate.sh fast` step (`RELEASE_HEALTH=0` skips). Logic in `server/telemetry-worker/scripts/releaseHealth.ts`; `RELEASE_HEALTH_FIXTURE` replaces the network. Tests: `tests/shell/test_release_health.bats` |
| `latest-green-sha.sh` | The commit `/release` cuts from: the newest push to `--branch` (default `main`) still on `origin/<branch>` whose push-triggered workflow runs all completed `success`/`skipped`, with every `--require` workflow (default `Build,Code Quality`) among them as `success`. Each commit passed over is named on stderr with why (in progress, failed, cancelled, never ran). A newest push with only cancelled runs prints `gh run rerun <id>` and exits 3 (`--walk-past-cancelled` walks back). Reads `gh` and git only. Tests: `tests/shell/test_latest_green_sha.bats` |
| `dev-release.sh` | Local dev release workflow (build + package + upload) |
| `generate-manifest.sh` | Generates `manifest.json` from release archives. Used by CI and dev-release |
| `ci/gpu_libs_hidden_smoke.sh` | The `gpu-libs-hidden-smoke` jobs: in `.github/workflows/release.yml`, which the release waits on, and nightly on main in `ccache-warm.yml` on its x86 build. Runs a packaged Pi/x86 `helix-screen` as root in the x86 toolchain image, with libdrm, libgbm, libEGL, libGLESv2 and libinput installed, then moved away: `--probe-egl` must exit 1, then 3, and the app under `--test` with no backend forced, `drm` and `egl` must reach the framebuffer, call nothing in a missing library and outlive a 20s timeout. `/dev/fb0` is a regular file whose ioctls `ci/fake_fbdev.c` answers (LD_PRELOAD). Tests: `tests/shell/test_gpu_libs_hidden_smoke.bats` |
| `esp32_package_release.sh` | Bundles a built K-Touch firmware into `helixscreen-esp32-ktouch-<tag>.zip`: merged factory image, `flash_args` and its images, README. Refuses an image that would reach the `cfg` settings partition. Run inside the `espressif/idf` image by `.github/workflows/esp32-build.yml` when `release.yml` calls it. Tests: `tests/shell/test_esp32_package_release.bats` |
| `version-compare.sh` | **Semver precedence for shell consumers** - `version-compare.sh A B` prints `-1`/`0`/`1`, and a version it cannot parse is a non-zero exit rather than a verdict. The `Guard against channel downgrade` step in `.github/workflows/release.yml` asks it whether publishing moves a channel's manifest forward; `sort -V` cannot answer, it ranks `1.1.0` below `1.1.0-beta.1`. Ordering cases live in `tests/fixtures/version_precedence.txt`, shared with `src/util/version.cpp`; `tests/shell/test_version_compare.bats` asserts the whole matrix |
| `r2-prune-plan.sh` | **What an R2 prune may delete** - `plan RETAIN [PINNED...]` takes versions on stdin and prints the ones to delete: never a version a channel manifest names, otherwise all but the RETAIN highest by semver. `pinned` reads each channel's `manifest.json` from the bucket and fails if any is unreadable, so the prune is skipped rather than run blind. Used by the release and symbol prunes in `release.yml` and `cleanup-r2.yml`. Tests: `tests/shell/test_r2_prune_plan.bats` |
| `android-version-code.sh` | **The single definition of the Android versionCode** - `(major*1000000 + minor*1000 + patch)*100 + ordinal` from `VERSION.txt`, where the ordinal encodes the prerelease suffix (`-alpha.N`/`-beta.N`/`-rc.N`, 99 for a release), plus the lane-overflow guard. `android/app/build.gradle`, `generate-whatsnew.sh` and `.github/workflows/release.yml` all call it; `tests/shell/test_android_version_code.bats` fails on a second copy of the arithmetic |
| `generate-whatsnew.sh` | Writes the Play Store "What's new" file under `android/fastlane/` from `android/whatsnew/<version>.txt`, verbatim, over 500 UTF-16 units a hard error. A stable version without that file fails; a prerelease without one gets its `CHANGELOG.md` section distilled (markdown stripped, cut on a sentence boundary). Tests: `tests/shell/test_generate_whatsnew.bats` |
| `changelog-section.sh` | `VERSION [CHANGELOG]`: prints that version's `CHANGELOG.md` section with HTML comments removed. The one extractor for everything that publishes a section: `generate-whatsnew.sh`'s fallback, and the Discord post and update-manifest notes in `.github/workflows/release.yml`. Tests: `tests/shell/test_generate_whatsnew.bats` |
| `generate-upload-keystore.sh` | One-time generation of the Android upload keystore. Output belongs in `~/.android-keystore/`, never in the tree |

### Translation / i18n
| Script | Purpose |
|--------|---------|
| `generate_translations.py` | Main translation generator - YAML → runtime XML packs. A key holding a real newline or tab survives the XML parse only as a `&#10;`/`&#9;` character reference; `escape_xml_attr()` says why |
| `translation_packs.py` | The `ui_xml/translations/` files no locale loads: the merged `translations.xml` and the identity locale's pack, read from `kIdentityLocale` in `include/translation_loader.h`. Imported by `platform_manifest.py` (release prune) and `esp32_stage_assets.py`; `android/app/build.gradle` restates the list and `tests/python/test_translation_packs.py` fails if it drifts |
| `translation_sync.py` | Sync keys (XML/C++ → YAML); also `coverage`, `obsolete`, `glossary` subcommands |
| `translations/yaml_manager.py` | Reads/edits the locale YAMLs by **line splice**, never a re-dump (no dump config reproduces the committed files byte-for-byte). `load_yaml_file()` refuses a file that defines a key twice: a later placeholder would otherwise silently replace the translation. Gated by `tests/shell/test_translation_duplicate_keys.bats` |
| `translations/` | Python package: extractor, YAML manager, coverage, glossary, CLI |

**Terminology consistency:** `translations/GLOSSARY.md` (`make translation-glossary`) pins canonical per-language renderings of recurring terms. Reuse the glossary term when translating, human or agent, and `grep` the locale before coining a new word for an already-translated concept. After changing a canonical term, add its English key to `GLOSSARY_GROUPS` in `translations/glossary.py` and regenerate.

#### Printer Hardware Profile Pipeline

Composable pipeline for improving `printer_database.json` from real-world telemetry:

```bash
# 1. Pull raw telemetry events to .telemetry-data/events/
./scripts/telemetry-pull.sh --since 2026-01-01

# 2. Analyze: aggregate by model, find discriminators, cluster unknowns
./scripts/telemetry-printer-profiles.py --json --candidates > /tmp/analysis.json

# 3. Interactively update printer DB and generate presets
./scripts/telemetry-update-printer-db.py /tmp/analysis.json
```

**Data flow:** client `hardware_profile` events → Worker R2 → `telemetry-pull.sh` → `.telemetry-data/events/` → `telemetry-printer-profiles.py` (aggregate per detected model) → `telemetry-update-printer-db.py` (diff against `printer_database.json`, walk the operator through changes).

### Quality & Auditing

A gate's header explains what it prevents and why the obvious alternative is wrong. `check_<name>.py`
has its meta-test at `tests/shell/test_<name>_gate.bats`; a row cites the test only when it lives
elsewhere. Rows carry what a gate fails on and its opt-out marker.

| Script | Purpose |
|--------|---------|
| `quality-checks.sh` | Pre-commit and CI quality checks (single source of truth). The driver: mode, path gating, the parallel fan-out and the result cache. Each gate is one file, `qc/<gate>.sh`, holding its `qc_<gate>` function and the `QC_TRIGGER_qc_<gate>` staged-path regex that decides whether `--staged-only` runs it; `QC_ALL` lists them in report order and the driver sources each by name, so a missing file fails the run. `QC_PUSH_ONLY` names the slow gates `--staged-only` defers to pre-push and land-gate, so a commit costs seconds (`HELIX_QC_ALL_AT_COMMIT=1` runs them anyway); a commit syntax-checks its staged sources and one includer per staged header instead of building. Helpers they share live in `qc/_lib.sh`. Tests: `tests/shell/test_quality_push_only.bats` |
| `run_suite_report.sh` | Produce the shared `--success` Catch2 report that `check_vacuous_tests.py` and `check_test_order_dependence.py` both read (`make suite-report`, and the nightly's own step). One unsharded process with its stdout discarded, so the report's byte count is the only progress signal there is: the script prints which case the run is inside, and stops it - naming that case - when the report stops growing (`SUITE_REPORT_STALL_SECS`) or the wall clock runs out (`SUITE_REPORT_MAX_SECS`). A red suite still yields a usable report. Meta-tests: `tests/shell/test_suite_report_guard.bats` |
| `check_doc_refs.py` | Doc-reference gate over every `CLAUDE.md`, `.claude/skills/`, `docs/README.md` and `docs/devel/**`: dead backticked paths, dead markdown links, docs/devel index completeness. Proves the FILE exists; whether a `#name` still resolves is `doc_anchors.py`'s question. `--devel [kPaths]`, `--stale` (report-only). |
| `doc_anchors.py` | Resolves a citation that names a place - `` `src/printer/printer_state.cpp#update_from_status` ``, quoted segments for names with spaces or overloads - to today's line, so no doc commits a line number. `--check` is advisory (`make check-doc-anchors`, from `.githooks/pre-push`) and also reports bare `:NNN` refs; `--render <dir>` backs `make docs-pinned`. Tests: `tests/python/test_doc_anchors.py` |
| `check_translation_format_specifiers.py` | Fail if a translated printf/`fmt::format` string (via `lv_tr()`) changes placeholder count/type vs its English source (#1073), or if a stored key/value holds an unresolved C escape (`\xNN`, `\n`, `\"`, ...). Gated on real format-sink usage, so prose `%`/`{}` never false-positive |
| `check_cjk_font_staleness.sh` + `check_cjk_font_coverage.py` | Fail if the runtime CJK font (`assets/fonts/cjk/*.bin`) is missing a codepoint the translations need. Staleness diffs the needed set — extracted by `translations/cjk_charset.py`, the same extractor `regen_text_fonts.sh` bakes from — against `.cjk_codepoints.manifest`; coverage parses the .bin cmap tables themselves (`lv_binfont_loader.c` layout) so a stale bake cannot hide behind a freshly written manifest. A missing glyph renders as tofu in zh/ja with no other symptom. Both run from `qc_cjk_fonts` on tracked files only - no `.otf` source fonts needed, so they hold in every clone and CI runner. Meta-tests: `tests/shell/test_cjk_font_staleness_gate.bats`, `tests/shell/test_cjk_font_coverage_gate.bats` |
| `check_update_queue_leaks.py` | Ratchet on cross-test UpdateQueue leaks (#1166): `[ISOLATION-LEAK]` reports in a test log vs `scripts/update_queue_leak_baseline.txt`, keyed `tag:<producer>` when tagged and `test:<victim>` otherwise, plus a `max-untagged-callbacks:` ceiling. The log needs `2>&1`. Meta-tests: `tests/shell/test_update_queue_leak_gate.bats` |
| `check_asan_leaks.py` | Ratchet on LeakSanitizer at-exit leaks (#1279) vs `scripts/asan_leak_baseline.txt`: direct leaks only, keyed `<file>::<function>` normalized to be compiler-agnostic, plus byte/object ceilings. Refuses a truncated log or one holding a non-leak ASan error. Run from `make test-asan`. Meta-tests: `tests/shell/test_asan_leak_gate.bats` |
| `tsan_resplit_shard.sh` | `make test-tsan`'s retry for a shard that died on TSan's reporter abort (#1293): reads the shard's test names, checks they round-trip exactly through Catch2's `--input-file`, then re-runs them in 2, 4, 8 pieces, carrying only aborting pieces forward. A finding in any piece is exit 3 and never retried; still-aborting tests are named in the shard log (exit 4, INCONCLUSIVE). Meta-tests: `tests/shell/test_tsan_resplit_shard.bats` |
| `triage_shard.sh` | The unit sweep's post-mortem for a failed shard (`diagnose_shards` in `mk/tests.mk`): names the failing case(s) from the shard log (`catch2_shard_tests.py --failed-in`), re-runs them alone, alone pinned to one CPU (`taskset -c`), as the same shard, and as the same shard pinned, and prints one verdict - fails alone, fails only pinned (timing), fails only in shard composition (with the repro command), or did not reproduce. ## Key Patterns

- **`helix-claim jobs` is make's `-j` only.** With a jobpool live it prints the whole pool, which a make draws from and anything else would run on top of. Work outside make sizes itself with `scripts/helix-claim hold [--min M] -- cmd` (exports `JOBPOOL_SLOTS`), and a container goes through `pool-docker.sh`. Called outside a make with a pool live, `jobs` says so on stderr; its stdout is always the bare number, since make and `SHARD_CONCURRENCY` parse it
- **Generated installers**: `install.sh` and `uninstall.sh` are bundled from `lib/installer/` by `make installer` into `build/installer/` and are not in git; edit the modules. The tracked `scripts/install.sh` is not that bundle: it is the bootstrap that keeps the raw GitHub URL for main/scripts/install.sh working, downloading `https://releases.helixscreen.org/install.sh` and running it with the same arguments
- **Telemetry credentials**: Scripts auto-load from `.env.telemetry` in project root. Set `HELIX_TELEMETRY_ADMIN_KEY` env var
- **Asset regeneration**: via Makefile targets (`make regen-fonts`, `make regen-images`), not directly
- **Python deps**: telemetry scripts need pandas; install `telemetry-requirements.txt` into the project `.venv/`
