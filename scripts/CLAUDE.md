# scripts/

Build, asset generation, deployment, and developer tooling for HelixScreen.

## Categories

### Installation & Deployment
| Script | Purpose |
|--------|---------|
| `install.sh` | **Auto-generated** single-file installer for end users (`curl\|sh`). Do NOT edit directly |
| `install-dev.sh` | Modular dev installer — uses `lib/installer/` modules. Edit this one |
| `uninstall.sh` | **Auto-generated** single-file uninstaller. Do NOT edit directly |
| `bundle-installer.sh` | Bundles `install-dev.sh` + `lib/installer/*` → `install.sh` |
| `bundle-uninstaller.sh` | Bundles uninstall modules → `uninstall.sh` |
| `helix-launcher.sh` | Systemd-launched watchdog wrapper. Sources `helixscreen.env` for runtime config |
| `check-deps.sh` | Validates build dependencies. `--minimal` for cross-compile environments |
| `device-env-set.sh` | Idempotently set one `KEY=VALUE` in a deployed device's `helixscreen.env` over ssh. Every deploy target EXCLUDES that file so a redeploy never clobbers local settings — which also means nothing in a deploy can turn on a runtime switch, and a build flag like `ENABLE_REMOTE_CONTROL=yes` bought nothing on the device. `mk/cross.mk`'s `sync-device-features` calls this when `bin/.build-features` says the binary has the subsystem. Backs the file up once (`.helix-bak`), rewrites a commented-out key in place rather than appending a duplicate, and leaves a matching value alone so an explicit opt-out survives redeploys |
| `device-env-set-remote.sh` | The half of the above that runs ON the printer, piped to `sh -s`. Separate file so it is testable without hardware (`tests/shell/test_device_env_set.bats`). POSIX sh — the K1/AD5M/CC1/K2 are BusyBox ash. Two hazards it exists to handle: `PI_DEPLOY_DIR` is `~/helixscreen` and a tilde inside a variable never expands, so `mkdir -p` would build a directory literally named `~`; and `sed -i` on a symlink writes a regular file OVER the link, which on the Snapmaker U1 would silently detach the device from its real config |

### Translation / i18n
| Script | Purpose |
|--------|---------|
| `generate_translations.py` | Main translation generator — YAML → runtime XML packs (`--emit-lv-i18n` for the legacy unlinked C table). `escape_xml_attr()` emits newline/tab/CR as `&#10;`/`&#9;`/`&#13;`: XML attribute-value normalization collapses a *literal* control character to a space, so a character reference is the only way a key containing a real newline survives the parse |
| `translation_sync.py` | Sync keys (XML/C++ → YAML); also `coverage`, `obsolete`, `glossary` subcommands |
| `translations/yaml_manager.py` | Reads/edits the locale YAMLs. Edits are **line splices**, never a re-dump — no dump config reproduces the committed files byte-for-byte, so re-serializing to add one key reflows thousands of unrelated lines. `load_yaml_file()` **refuses a file that defines a key twice**, because neither backend is safe there: ruamel raises `DuplicateKeyError` buried under a dozen constructor frames, and `pyyaml.safe_load` keeps the LAST value — an empty placeholder sitting after a translated entry does not error, it deletes the translation on the next write. That shipped: a branch cut before the locales were filled ran `translation-sync`, merging brought main's translated entries in beside its placeholders, YAML merges textually so both survived, and `Print cancelled` / `Print did not start` rendered as English in all eight non-English locales. Detection is left to the parsers, not a regex — long keys are folded across lines or use YAML's explicit `? key` form, and a line scan missed 59 keys per file. Gated by `tests/shell/test_translation_duplicate_keys.bats` |
| `migrate_xml_translations.py` | Migration tool: inline XML text → translation key references |
| `xml_to_yaml_translations.py` | Extract inline XML strings to YAML format |
| `translations/` | Python package: extractor, YAML manager, coverage, glossary, CLI |

**Terminology consistency:** `translations/GLOSSARY.md` (generated by `make translation-glossary` / `translation_sync.py glossary`) pins canonical per-language renderings of recurring terms. When translating new strings — human or agent — reuse the glossary term and `grep` the locale for any other recurring word; don't coin a new word for an already-translated concept. `make translation-sync` prints a reminder. Regenerate the glossary after introducing/changing a canonical term (add its English key to `GLOSSARY_GROUPS` in `translations/glossary.py`).

### Telemetry & Crash Analysis
| Script | Purpose |
|--------|---------|
| `telemetry-pull.sh` | Pull events from telemetry worker API. Needs `HELIX_TELEMETRY_ADMIN_KEY` |
| `telemetry-analyze.py` | Adoption, reliability, crash metrics. Output: terminal/JSON/HTML |
| `telemetry-printer-profiles.py` | Printer detection analysis: model distribution, name clustering, candidate heuristics, DB validation |
| `telemetry-update-printer-db.py` | Interactive updater: consumes profile analysis, walks operator through augmenting/creating printer_database.json entries and presets |
| `telemetry-crashes.py` | Resolve ASLR crash addresses → function names, group by signature. `--anomalies` mode surfaces non-fatal `error_encountered` events (default code: `bg_tok_expired_check` for L081/cluster:pstat-async-delete watch); resolution uses the `runtime_anchor=` field embedded by helix_lvgl_anomaly (v0.99.60+). Pre-v0.99.60 bundles fall back to raw hex on PIE platforms. |
| `telemetry-backfill.sh` | Backfill Analytics Engine from R2 (90-day retention limit) |
| `resolve-backtrace.sh` | Resolve raw backtrace addresses using `.sym` files from R2. `--bundle <debug-bundle.json>` auto-extracts the raw recent crash (`crash_txt`), **warns when the bundle's `crash_report` is a different/older crash** (the dual-crash trap), splits reliable PC/RA+fp-walk frames from noisy stack-scan candidates, and prints a filtered **app-code call spine**. Also prints a **crash-context analysis**: infers the crashing thread from resolved frames (libhv WS loop / HTTP worker / spawned worker = BACKGROUND vs main/LVGL), decodes `event_code` → `LV_EVENT_*` name, and **flags when the header's `event_target`/`event_code`/`queue_prev`/`recent_error` are ambient main-thread state that's misleading for a background-thread crash** (the trap that derailed bundle UK9QCFY3 into a phantom lv_label UAF). Also `--crash-file <crash.txt>` and `--issue <N>` — the latter reads **both** worker output shapes (the resolved `| # | addr | symbol |` table and the bare fenced code block emitted when no symbol file was found), splits a `## Stack Scan` section off as candidates, and scans **only** those sections: the Registers / All Registers tables hold SP and r0-r12, and resolving those as frames invents call sites (it used to, yielding 3 "frames" for a 26-frame crash — #1240). `--bundle` reads the platform from the bundle's `system.platform` — no need to pass it. All addresses go through **one** `addr2line` (a process per address re-read the multi-GB `.debug` and ballooned to ~9.5GB each; see [L090]) |
| `debug-bundle.sh` | Fetch and display debug bundles from `crash.helixscreen.org` |
| `freeze-drops.sh` | Aggregate L081 Mechanism D `DROPPED (frozen)` events across device logs / debug bundles / files; cross-references each tag to source location and notes whether it's already using `defer_critical`. Use proactively to catch first-fire-callback regressions before users hit them: `./scripts/freeze-drops.sh --ssh root@192.168.1.74 --ssh root@192.168.30.103` |

#### Printer Hardware Profile Pipeline

Composable pipeline for improving `printer_database.json` from real-world telemetry:

```bash
# 1. Pull raw telemetry events to .telemetry-data/events/
./scripts/telemetry-pull.sh --since 2026-01-01

# 2. Analyze: aggregate by model, find discriminators, cluster unknowns
./scripts/telemetry-printer-profiles.py --json --candidates > /tmp/analysis.json

# 3. Interactively update printer DB and generate presets
./scripts/telemetry-update-printer-db.py /tmp/analysis.json
```

**Data flow:** Client `hardware_profile` events (fans, sensors, steppers, LEDs, macros, MCUs, build volume, full Klipper object list) → Worker R2 storage → `telemetry-pull.sh` → local `.telemetry-data/events/` → `telemetry-printer-profiles.py` aggregates per detected model → `telemetry-update-printer-db.py` diffs against `printer_database.json` and walks operator through changes.

| `check_update_queue_leaks.py` | Ratcheting gate on cross-test UpdateQueue leaks (#1166). Keys by ATTRIBUTION QUALITY, not by victim: a tagged producer keys `tag:<producer>` and its victim test is deliberately discarded; an `<untagged>` producer falls back to `test:<victim>`. Victim-keying everything was #1170 — the victim is whichever test drained next, so debounce-driven producers move between innocent tests on wall-clock timing (the victim set moved by 4 tests across four identical runs; the tag set did not move at all). Producer-keying everything is not available either: 266 of ~305 reports are `<untagged>`. The baseline also carries a `max-untagged-callbacks:` ceiling, since the key set alone cannot see an already-listed test start leaking *more*; only the untagged half is counted because the tagged half is the timing-driven one. `--max-allowed N` exists but is the weaker mode. | `check_asan_leaks.py` | Ratcheting gate on at-exit leaks under AddressSanitizer (#1279). Parses the LeakSanitizer report out of an ASan run log and fails on any leak origin absent from `--baseline scripts/asan_leak_baseline.txt`. Only DIRECT leaks are keyed — an indirect leak is a child of a direct one, and counting both double-counts the same defect. Keys are `<file>::<function>` normalized to be SYMBOLIZER-AGNOSTIC: line numbers and clang's trailing column dropped, absolute checkout prefixes relativized (existence-checked against the repo, so `/usr/src/...` stays foreign), return types dropped, gcc's `{lambda(...)}`/clang's `$_n` collapsed to `lambda`, `[abi:...]` tags stripped, template argument lists truncated to the first argument, parameter lists dropped, and Catch2 `CATCH2_INTERNAL_TEST_<n>` numbering collapsed — the nightly builds with clang and a local `make test-asan` may use gcc, and the 2026-08-16 nightly failed on all 23 origins because the baseline held only one compiler's spelling. | `check_drm_mmap_lfs.py` | Fail if LVGL's DRM driver can mmap a dumb buffer through a 32-bit `off_t`. DRM allocates the fake map offset from `DRM_FILE_PAGE_OFFSET_START` (4 GiB), so every offset is above 2^32; without large-file support in `lv_linux_drm.c` the offset truncates at the `mmap()` call and the mapping fails with EINVAL. Nothing observes this from x86_64 and the symptom is silent — one `mmap fail` line, then the fbdev fallback — so what is gated is the shape of the fix: `patches/lvgl-drm-mmap64.patch` exists, `mk/patches.mk` applies it, and the patch still ADDS both `#define _FILE_OFFSET_BITS 64` and the `sizeof(off_t)` assertion (a define present only as patch context does not count). Meta-tests in `tests/shell/test_gcode_lfs_gate.bats` |
| `check_gcode_error_ownership.py` | Hard gate at zero: fail if an `execute_gcode()` call passes an inline `(const MoonrakerError&)` lambda whose body is *entirely* logging (or empty) without declaring `caller_surfaces_errors`. That parameter means "my `on_error` actually SHOWS a human something"; the default is `true`, so a log-only callback claims the report by saying nothing. The consequence is silence, not noise: `MoonrakerRequestTracker` records the rejection in `rpc_error_correlation`, `GcodeErrorRouter` then suppresses its own report of Klipper's `!!` broadcast for the same failure, and a rejected macro is reported by NOBODY. Invisible in review because the call site looks handled — there IS an error callback, it just writes to a log. Only `execute_gcode` is scanned: plain JSON-RPC methods have no `!!` channel, so the tracker's generic fallback is their only surface and the rule does not apply. Deliberately conservative — any `UI_MARKERS` hit (`NOTIFY_`, `Modal`, `lv_subject_`, `AmsErrorHelper`, …) in the body means it plausibly reaches a human and the site is left alone, because a gate that cries wolf gets switched off. `*_mock.*` files are skipped, matching `tests/shell/test_code_lint.bats`. Passing the parameter with ANY value silences it (supplying it is the deliberate choice); otherwise annotate `// ERROR_OWNERSHIP_OK: reason` in the call or ~400 chars above it. The comment/string blanker is length-preserving and asserts on drift — an earlier version emitted one space for a two-char escape, shifted every subsequent offset, and reported a site that already carried the parameter. `--list` / `--summary` / `--max-allowed`. Contract: `include/rpc_error_policy.h`, `docs/devel/RPC_ERROR_OWNERSHIP.md` |

A dangling reference is silent at runtime — `get_prerendered_printer_path()` falls through to `generic-corexy` and logs nothing above debug, so a bed-slinger or delta just quietly renders as a CoreXY frame; 20 of 97 entries had drifted that way. `KNOWN_MISSING` is a ratchet, not an exemption: the gate fails on a NEW dangling reference *and* on a listed image whose art has since landed, so the list can only shrink. `--list` prints every unresolved reference with `(known)`/`(NEW)` |
| `check_pytest_asyncio_deps.py` | Fail if the Python suites' async support is used but not declared. Two rules. (1) An `async def test_*` exists and `requirements.txt` doesn't list pytest-asyncio: plain pytest doesn't skip or error on collection — it runs the case, gets a coroutine, and fails it with `async def functions are not natively supported`, so CI reads as N broken tests rather than a missing plugin. That is exactly how Build stayed red for a day while the suite passed on a `.venv` with the plugin installed by hand. (2) An `async def test_*` with no `@pytest.mark.asyncio` — pytest-asyncio defaults to **strict**, which SKIPS it, so the suite goes green having run nothing. Rule 2 drops when a pytest config sets `asyncio_mode = auto`; a module-level `pytestmark` also satisfies it. Uses `ast`, so nested async helpers and non-`test_` async fixtures are not miscounted. Silent on a repo with no async tests. `--list` / `--test-dir` / `--requirements`. Meta-tests in `tests/shell/test_pytest_asyncio_deps_gate.bats` |
| `check_modal_chrome_budget.py` | Fail if a modal's chrome does not match the content cap it budgets against (#1277). `#dialog_content_max` is ONE global ladder derived from modal_dialog.xml's shape — header + scrollable content + divider + button row ≤ 85% of the screen — and `lv_flex.c` implements grow only (no CSS-style shrink), so when children total more than the cap the overflow falls off the BOTTOM and takes the dismiss button with it: ams_loading_error_modal's button row sat 11px past the card bottom on 480x272, leaving a modal the user could not dismiss. Everything except a divider and the first button row must live INSIDE the scroll container; where extra chrome must stay visible while text scrolls, the container opts into the sibling token measured for that shape — `#dialog_content_pinned_max` (one pinned block below the scroll area) or `#dialog_content_tall_chrome_max` (a second button row) — each reserving exactly one extra block of height. Also flags a card raised above the shared 85% cap (`style_max_height="90%"` unsizes the ladder arithmetic every modal shares). Not flagged: dividers, siblings bound to the same subject with different `ref_value`s (never visible together, heights don't sum), modals that cap themselves without any shared token. Opt out with `MODAL_CHROME_OK: <reason>` anywhere in the file |
| `check_raw_print_job_state.py` | Every read of the raw print wire must say why it is not on the lifecycle. `helix::PrintJobState` is what `print_stats.state` said; it cannot express a job the app has committed to but the printer has not reported yet, so a semantic question asked of it — "does a job own the toolhead right now?" — is blind for the whole pre-print window. That blindness shipped: 21 motion controls stayed enabled while the toolhead homed and probed, and a queue tap deleted the job it then failed to start. The gate does NOT forbid the wire (~80 sites legitimately want it: the parse itself, terminal-outcome formatting, telemetry's phase tracker); it forbids reading it silently, because a reader cannot tell a deliberate wire read from one that predates the lifecycle — and the difference is a bug class. Flags `PrintJobState::PRINTING/PAUSED/STANDBY`, `get_print_job_state()` and `get_print_state_enum_subject()` without `// RAW_PRINT_STATE_OK: <real reason>` within 12 lines above (a switch's arms share one comment); "keeping raw" is not a reason. Baseline 0 over ~80 marked sites. The derivation layer (`print_lifecycle_state.cpp`, `printer_state.cpp`) is allowlisted — naming every arm is that file's job. Ask `state.get_print_lifecycle()`, `job_holds_machine(lifecycle)`, or `observe_print_lifecycle()` instead |
| `check_print_state_cast.py` | Reject hand-casting `lv_subject_get_int()` into `PrintState` or `PrintJobState`. The getter returns int, so the cast compiles against WHICHEVER subject the author happened to name — and the two enums share no numbering past index 0 (`STANDBY=0 PRINTING=1 PAUSED=2 COMPLETE=3` vs `Idle=0 Preparing=1 Printing=2 Paused=3`), so a COMPLETE job reads back Paused and a PRINTING one Preparing. That exact mistake shipped twice while migrating guards onto the lifecycle (ams_backend_ad5x_ifs, power_device_state), and both times the code compiled, ran, and answered a different question. Also catches the cast landing in an observer lambda 3–30 lines from the `get_*_subject()` call that picked the enum — a reader cannot check the pairing at a glance, which is the whole hazard. Use the typed accessors (`state.get_print_lifecycle()` → `PrintState`, `state.get_print_job_state()` → `PrintJobState`) and the typed observer factories, which pair each subject with its own enum. Opt out with `// PRINT_STATE_CAST_OK: <reason>`; the derivation layer and `observer_factory.h` (where the pairing is supposed to live) are allowlisted |
| `android-version-code.sh` | Not a `check_*` gate itself, but `tests/shell/test_android_version_code.bats` gates it: known packings and the `versionCode(0.99.113) < versionCode(1.0.0)` ordering invariant, overflow/malformed rejection, and a **divergence gate** that fails if `android/app/build.gradle`, `scripts/generate-whatsnew.sh`, or `.github/workflows/release.yml` grows a second copy of the arithmetic. Detection is a multiplication by a lane constant after comments are stripped, so prose explaining the formula is fine and a live computation is not; a mutation test keeps the detector honest |
| `audit_codebase.sh` | Check for coding standard violations. `--strict` for CI |
| `format-xml.py` | XML formatter: 2-space indent, attribute wrapping at ~120 chars. Skips generator-owned XML (`GENERATED_DIRS` = `ui_xml/translations/`, written by `generate_translations.py` on every build) — formatting those made a formatted tree go dirty on the next compile, and `make format` wrap them straight back. `mk/format.mk` and `quality-checks.sh` prune the same paths for their xmllint fallbacks; the *validation* pass still covers them. LVGL state selectors (`style_bg_opa:checked="0"`) read as a namespace prefix to every XML parser, so they are round-tripped through `STATE_COLON_SENTINEL` — which must be made of XML NameChars, or the parser trips over the sentinel instead and reports the far more confusing "Specification mandates value for attribute". A file it cannot parse is counted as an ERROR, never as formatted: those two outcomes shared a return value, so `--check` printed "All files properly formatted" and exited 0 for files it had never read, and `filament_panel`/`input_shaper_panel`/`theme_editor_overlay` drifted unformatted behind it. The `quality-checks.sh` XML-formatting gate is advisory on purpose (`EXIT_CODE=1` is commented out); malformed XML is a hard failure via the separate xmllint validation pass earlier in that script. Under `--auto-fix` (the pre-commit path) it repairs and re-stages rather than only warning — purely advisory left a hole, since `test_format_xml_gate.bats` checks the WHOLE `ui_xml/` tree and fails hard, so one file sailing past the warning turned the shell suite red on main until someone noticed (`panel_widget_bypass.xml`, from `58ea1eea2`). A **partially staged** file is formatted on disk but deliberately NOT re-staged: `git add` takes the whole working-tree file, so re-staging one would commit hunks its author held back. Meta-tests in `tests/shell/test_format_xml_gate.bats` |

## Key Patterns

- **Auto-generated files**: `install.sh` and `uninstall.sh` are bundled from modular sources. Edit the dev versions + `lib/installer/`, then re-bundle
- **Telemetry credentials**: Scripts auto-load from `.env.telemetry` in project root. Set `HELIX_TELEMETRY_ADMIN_KEY` env var
- **Asset regeneration**: Usually invoked via Makefile targets (`make regen-fonts`, `make regen-images`) rather than directly
- **Python deps**: Telemetry scripts need pandas — install from `telemetry-requirements.txt` into project `.venv/`
